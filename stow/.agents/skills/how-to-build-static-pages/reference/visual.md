# Visual rules

Use these Refactoring UI rules. Take all values from BRANDING.md. Do not make values for one page.

## Content and style

- Decide what the reader must do or understand. Build the smallest layout for that message.
- Add detail after the structure works. Finish one section before you start the next.
- Use one style across the project: serious, playful, minimal, bold, warm, or technical.
- Use one heading font, one body font, one primary color, and one accent color.

## Visual order

- Decide what the reader sees first, second, and third.
- Show that order with size, weight, color, and space. Do not use size alone.
- Reduce emphasis on secondary elements before you increase emphasis on the main element.
- Make the primary action clear. Do not give two buttons the same weight.
- Remove labels when the value is clear without them.
- Use heading levels for structure, not size.

## Type

- Use the brand type scale. Common sizes are 12, 14, 16, 20, 24, 32, 48, and 64 pixels.
- Use no more than five sizes per page. Keep text lines between 45 and 75 characters.
- Use line height near 1.5 for body text and 1.1 to 1.25 for large headings.
- Reduce letter spacing in large headings. Increase it slightly in small uppercase labels.
- Align text to the reading edge. Do not center long paragraphs.
- Use near-black for body text. Use muted text only for secondary lines.

## Space and sticky elements

- Start with too much white space. Remove space when the page feels loose.
- Use the brand space scale. A common base is 4 or 8 pixels. Do not scale space with viewport size.
- Use more space between groups than inside groups. Do not fill the screen with extra content.
- Use the same vertical padding for sections. Change it only when the content needs a different rhythm.
- Use the container width from BRANDING.md.
- Use sticky elements only to help the reader find or use content. A navbar or article contents can be sticky.
- Do not make decorative elements sticky. Do not use sticky for a scroll effect.
- Keep sticky elements inside their sections. Do not let them cover content or occupy most of the screen.
- Test sticky elements on a short screen.

## Color and depth

- Define shades in BRANDING.md before use. Use the primary color for the main action and small accents, not large areas.
- Control saturation. Prefer a dark primary shade when a bright shade is too strong.
- Use grey with the brand hue. Do not use pure grey or cold grey with a warm brand.
- Do not use pure black. Do not use grey text on colored backgrounds. Use a darker shade of the background hue.
- Use color with a label, icon, or weight change to show a state.
- Follow reference/accessibility.md for contrast and text on photos.
- Use gradients only on charts or photo overlays. Do not use decorative gradients.
- Use shadows only to show layers. Keep one light source, usually above.
- Build shadows with a small ambient part and a larger direct part. Keep both soft and weak.
- Use borders, background changes, or space instead of shadows where possible.
- Do not combine a border, shadow, and background on one element. Remove borders between different backgrounds.
- Use a small overlap to show a layer without a shadow. Keep a flat design flat.

## Decoration and details

- Use a light pattern, soft surface change, or single accent line.
- Keep decoration behind content with low contrast. Remove decoration that competes with copy.
- Do not add blobs, waves, glows, or floating gradients.
- Follow reference/assets.md for images. Do not stretch small images.
- Start from browser defaults. Improve focus rings, selection color, scroll bars, and form fields.
- Add a border on one side of a card only when it has meaning.
- Give empty states a useful line and one action.
